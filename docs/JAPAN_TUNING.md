# 日本向け調整の記録

2026-11-03。所有者: Studio Yebisu。段階: 個人端末で検証する開発版。目的はGalaxy上で日本語を標準としてMikaを使うこと。原作のリリースとは別に扱う。

## 変更範囲

| 対象 | 調整 |

画面、エラー、診断、AIへの説明文とコードのコメントを日本語に揃える。JSONキー、ツール名、列挙値、パッケージ名、ドメイン名、APIの識別値、画面からの引用原文は動作に必要なデータとして扱う。中国語アプリの正式名・別名、画面を認識する辞書、都市コード表、外国語の画面を検証するテスト入力にも原文が必要になる。ユーザー向けの案内文と照合用データは区別する。

## 中国系サービスの既定値

中国系の接続先は海外リージョンも含め、初期画面では表示しない。必要な場合だけ「中国系を表示（任意）」を開いて選ぶ。OpenRouterやOpenCode Goでも、既知の中国系モデルを自動試行・自動設定の候補に戻さない。候補がなくてもembeddingなどの用途違いのモデルへ切り替えない。

中国系アプリ・サイトの資料は[任意資料](../optional/china/README.md)へ移し、標準APKのカタログには含めない。古い記録や明示的な利用を読む互換性テストでは、任意資料を別途読み込む。

本人が明示した接続先、ローカル実行、手動で選んだモデル、保存済みの接続情報は保持する。新しい接続先へキーや認証状態を自動で移さない。この方針はMika JPの標準候補に適用し、端末全体の通信を遮断する設定にはしない。

更新確認はこのフォークのGitHub、検索はBing、追加パッケージはAlpine公式を参照する。サンドボックスのネットワークとリレーは初期無効。これはソースと同梱物の調査結果であり、端末全体の通信を実測した結果ではない。

## 監査で修正・検証した回帰

指定されたOpus 5.5（実モデル識別子claude-opus-5-5）を既存のClaude Max接続で実行し、ソースと差分を読み取り専用で監査した。実行証拠と詳細レポートはローカルの検証記録に保存し、認証情報や端末の画面は渡さない。

- 漢字だけの日本語の名称・住所を外国語として拒否しない。
- 送信などがすでに実行された後、言語の再回答に失敗しても同じ操作の再実行を促さない。
- 検証理由は表示用の日本語とモデルへ戻す原文を分け、修正に必要な情報を落とさない。
- 円の分割表示や漢数字・位取りを含む金額を過少に承認しない。対応していない位取りは自動換算せず、金額不一致として止める。
- 日本語固定のために起動時の画面サイズや向きを固定しない。

## 確認方法

1. knowledgeIndexで見出し、パッケージ、ドメイン、相互参照、本文長を検査する。
2. 変更した操作判定、知識検索、学習、画面判定をJVMテストで確認する。
3. 日本語プロンプトとスナップショットの差分を確認する。
4. APKをビルドし、実機で日本語の固定、端末や旧設定の言語に影響されないこと、日本語OCRを確認する。
5. スマホ操作ヘルパーと互換性チェックを確認する。
6. AI接続後の実際のタスクは本人の認証後に確認する。

全アプリのログイン状態や全機能を検証したとは扱わない。実機で読めていない画面のラベルや座標を内蔵知識で固定しない。

## 初回公開候補 0.1.33-jp.3

2026-11-03、未統合だったrootブランチと公開準備を統合。上の実機検証は0.1.33-jp.2の記録であり、root機能や公開用署名の実機確認を含まない。

- root取得済み端末向けのヘルパー起動とrootコマンドを追加。両方とも既定無効で、本人が個別に許可する。確認モードでは変更コマンドの全文に対する承認を1回だけ使い、自律モードでは本人の設定に従って確認を省く。
- 読み取りコマンドの判定を保守化。未知の構文、任意の実行ファイル、環境変数の代入、未引用のファイル名展開などは変更として扱う。通常のヘルパーとrootコマンドの実行経路を分け、通常のヘルパーはUID・GIDとも2000であることを確認する。
- Windowsでcore 2,861件・app 1,457件を実行。既存105失敗に加え、日本語の省略表示とrootの案内文の2件を検出して修正した。修正後はcoreの対象212件で既存8失敗のみ・追加失敗0、appの対象38件で全件成功を確認した。プロンプトの再検査ではスナップショット更新を使わない。
- 既定と日本語の1,908項目を照合。ネイティブランチャーのコメントも日本語化し、Cの字句・実行時文字列・行数が変わらないことを確認した。同梱ネイティブバイナリは変更していない。
- 公開用署名の環境変数、配布物の検証、対応ソースの作成を追加。PRoot/tallocと、同梱実行環境のGPL/LGPL/MPL対象14系統の対応ソースを取得し、固定ハッシュを照合した。配布ツールのネットワーク不要の検査7件が成功。

Linux上の全体検査は[GitHub Actions](https://github.com/yebisu0529-ship-it/Mika-JP/actions/workflows/verify.yml)で確認する。Windows上のCLI接続テストは、引用符を含む入力の保持で失敗しているため、Linux CIの結果と区別する。公開元の版・コミット・署名・ABIは配布時のrelease-manifest.jsonに記録し、同じReleaseへ対応ソースとSHA256SUMSを添付する。署名鍵の管理と一般公開は[公開手順](release.md)に従う。

## 説明文と原文データの扱い（2026-11-03）

jp.4向けの説明文監査では、人間向けの説明と既定の出力を日本語に揃えます。法的な原文、著作権表示、外国の画面を認識する語、検索対象の固有名詞と、その回帰テストは照合に必要な原文を保持します。中国語の入力やデータをすべて削除したという意味ではありません。公開済みの版の資産とは分け、今回の変更範囲と確認結果を記録します。

## 支払い時の一時停止（0.1.36-jp.2）

通知の「支払いのため一時停止」で、Mika自身のユーザー補助とその自動復旧を止めます。停止を確認すると、通知の操作は「Mikaを再開」に切り替わります。支払いを終えて決済アプリを閉じてから再開してください。停止中は画面を変更するツールも待機し、タスクの「続行」ではこの停止を解除しません。

停止状態はアプリや端末の再起動後も保持します。時刻や決済アプリの終了を推測した自動再開はしません。元のユーザー補助の設定と、ほかのユーザー補助サービスを保持し、再開できなかった場合は停止を維持して案内します。通知を消した場合は「設定 → 復旧と修復」から同じ操作ができます。新しい権限やrootは不要です。PayPay自体の起動や決済は行いません。
